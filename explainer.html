Bahi बही for chartered accountants

Accounting that lives in a file, not on someone's server.

Every client's complete books — invoices, purchases, ledger, GST, audit trail — in a single .khata file on a disk you control. No server. No account. No subscription. Nothing leaves the client's machine.

Why CAs use it

1

The client's data stays the client's

The books live in a .khata file on disk and are read and written locally in the browser. Nothing is uploaded; there is no cloud copy to subpoena, breach, or hold hostage. You review a file the client hands you.

2

GST & TDS, generated — not re-keyed

GSTR-1, GSTR-3B, CMP-08, Form 26Q / 27EQ / 27D, e-way bills, RCM, ITC eligibility and compensation cess all flow from the same double-entry ledger. Portal-ready JSON and NSDL-compatible CSV out of the box.

3

Tamper-evident by construction

Every state-changing action is recorded in an append-only, SHA-256 hash-chained, digitally-signed audit log. You can see exactly what the owner did since the last hand-off — and a single edited row breaks the chain visibly.

4

A review mode that's actually yours

Open in CA mode and your annotations, adjustment vouchers and review report are tagged to you and your ICAI membership — layered on top of the owner's books without ever altering their entries.

5

Bring the old books with you

Import Tally Prime and Tally ERP 9 XML — masters and vouchers — through a guided, dry-run-first wizard. Snapshots freeze each posting's identity and rates so reprints stay correct forever.

6

An open format — no lock-in

The .khata file is just a zip of a SQLite ledger plus a manifest and audit log. The format is a published open standard; any tool can read it. Bahi is one implementation, not a walled garden.

How it works

A .khata file is a company's books — there's nothing else to set up. It opens in any Chromium browser (Chrome, Edge, Brave, Arc); the browser is the entire application. No install, no login, no telemetry.

One file per client. You decide where it lives — a client folder, an encrypted drive, wherever your engagement requires. Hand it back when you're done; the audit log carries your review with it.

Open the file and unzip it any time: it's a plain SQLite double-entry ledger plus a JSON manifest. Your client's records outlive any single app.

# inside every .khata file
mybooks.khata
├── manifest.json  identity · integrity hashes
├── books.sqlite  the double-entry ledger
│           + the signed audit log
├── snapshots/  crash / corruption recovery
└── attachments/  scanned bills, etc.
